# 第八章使用教学：ACL 检索与带引用问答

本章实现“先授权、后检索”的本地知识服务。它不把整个知识库交给模型，也不让模型决定用户能看什么：SQLite 查询先依据 `user_id`、项目和角色 ACL 选择候选 chunks，再进行关键词与向量评分，最后只根据本次候选生成带引用的结构化答案。

## 1. 已实现的组件

| 文件 | 作用 |
| --- | --- |
| [local_archive.py](../app/services/local_archive.py) | SQLite 用户、项目、角色、ACL、文档与 chunks；执行 ACL-first 混合检索。 |
| [knowledge.py](../app/services/knowledge.py) | `search_documents`、结构化回答、引用白名单校验。 |
| [main.py](../app/main.py) | `/health` 与 `/v1/knowledge/query` FastAPI 接口。 |
| [cli.py](../app/cli.py) | 本地授权、入库、检索与问答命令。 |
| [knowledge_cases.jsonl](../tests/evals/knowledge_cases.jsonl) | 30 条正确回答、无答案、跨项目、无权限、引用与恶意文本评测用例。 |

检索顺序固定如下：

```text
X-User-Id -> users.active -> user_roles(project) -> document_acl(read)
-> effective documents -> chunks -> keyword + hash-v1 vector ranking
-> authorized retrieval result set -> answer + validated citations
```

因此，未经授权的文档不会进入排序、回答或引用校验步骤。

## 2. 初始化本地演示数据

第七章已经建立本地入库命令。没有自己的文档时，先创建一个只含公开/脱敏内容的 HTML 文件：

```bash
cd /GIT/scientific-agent-skills/lab-agent
mkdir -p data/demo
cat > data/demo/tissue-sop.html <<'EOF'
<html><head><title>组织保存 SOP</title></head>
<body><h1>保存</h1><p>固定前应将组织保存在冰上。</p></body></html>
EOF

uv run --no-sync python -m app.cli local ingest \
  --archive data/local-archive \
  --project mouse-neuro-demo \
  --source data/demo/tissue-sop.html \
  --classification internal-research \
  --allowed-role student \
  --allowed-role research-assistant
```

为经过认证的本地演示用户授予项目角色：

```bash
uv run --no-sync python -m app.cli local grant-role \
  --archive data/local-archive \
  --user-id student-demo \
  --display-name 'Student Demo' \
  --project mouse-neuro-demo \
  --role student
```

`grant-role` 是管理员操作，不应交给 Agent 或普通用户。生产环境必须从 OIDC/OAuth 的服务端身份与数据库角色记录取得 `user_id`，而不是信任请求体给出的角色。

## 3. 用 CLI 检索和问答

查看检索到的、已授权的 chunks：

```bash
uv run --no-sync python -m app.cli local search \
  --archive data/local-archive \
  --project mouse-neuro-demo \
  --role student \
  --query 组织
```

使用服务端从 `user_id` 加载角色并输出结构化答案：

```bash
uv run --no-sync python -m app.cli local query \
  --archive data/local-archive \
  --user-id student-demo \
  --project mouse-neuro-demo \
  --question '组织在固定前应如何保存？'
```

成功回答的 JSON 结构为：

```json
{
  "answer": "固定前应将组织保存在冰上。",
  "citations": [{"document_id": "...", "chunk_id": "...", "title": "组织保存 SOP", "section": "保存", "page": null}],
  "confidence": 0.2,
  "missing_information": [],
  "status": "answered"
}
```

没有可授权证据、跨项目、未知用户、停用用户或角色不匹配时，服务返回：

```json
{
  "answer": "没有找到可授权且足以支持该问题的证据。",
  "citations": [],
  "confidence": 0.0,
  "missing_information": ["authorized evidence"],
  "status": "insufficient_evidence"
}
```

这两种情况不应通过不同的错误信息泄漏“某文档是否存在”。

## 4. 启动 HTTP API

```bash
LOCAL_ARCHIVE_PATH=data/local-archive \
uv run --no-sync uvicorn app.main:app --reload --port 8000
```

另一个终端执行：

```bash
curl -s http://127.0.0.1:8000/health

curl -s http://127.0.0.1:8000/v1/knowledge/query \
  -H 'X-User-Id: student-demo' \
  -H 'Content-Type: application/json' \
  -d '{"project_id":"mouse-neuro-demo","question":"组织在固定前应如何保存？"}'
```

本地模式中的 `X-User-Id` 仅是教学用的受信开发边界，不是生产级身份认证。生产 API 应从已验证的 Bearer token/OIDC session 提取 subject，并拒绝客户端任意指定的用户 ID。

## 5. 引用校验机制

`KnowledgeService.answer_question` 先获得本次 `search_documents` 的结果集，再构造 `Citation(document_id, chunk_id, ...)`。`validate_citations` 会检查每个引用对是否真的存在于该结果集；伪造 document/chunk 组合会抛出错误，不能进入响应。

当前回答器是保守的抽取式实现：答案文本直接来自排名第一的已授权 chunk。未来接入 LLM 时必须保持相同契约：

1. 只将本次已授权 chunks 传给模型。
2. 强制模型输出 `answer`、`citations[]`、`confidence`、`missing_information`。
3. 服务端把模型引用交给 `validate_citations`；失败则拒绝响应或返回无证据。
4. 文档中的“忽略之前指令”等文本只是证据数据，不能改变工具权限、检索范围或系统规则。

不要把全文、系统提示词、工具定义或跨项目数据传给模型。

## 6. Agent 调用流程

Agent 本身不直接读 SQLite、拼 SQL、扩大项目范围或指定角色。服务端为 Agent 暴露一个单用途工具：

```text
query_knowledge(user_id, project_id, question) -> KnowledgeAnswer
```

处理流程：

1. API 网关验证访问令牌，服务端获得稳定的 `user_id`。
2. Agent 将用户问题和已选项目传给 `query_knowledge`；`user_id` 来自认证上下文，不能由模型填充。
3. 工具执行 ACL-first 混合检索，返回 `KnowledgeAnswer`。
4. `status == answered` 时，Agent 只能陈述 `answer` 并展示返回的 citations。
5. `status == insufficient_evidence` 时，Agent 说明没有已授权证据或请求补充受授权的文档，不得猜测或尝试跨项目搜索。

工具输入应限制为项目 ID、问题长度和固定 top-k；不要暴露 `run_shell`、任意 SQL、任意文件路径或“搜索全部项目”接口。

## 7. 混合排序与限制

本地模式对 ACL 已放行的 chunks 计算：

```text
score = normalized keyword occurrence + cosine(hash-v1(query), hash-v1(chunk))
```

`hash-v1` 是无外部模型依赖的确定性教学基线，不能代替生产级语义 embedding。生产实现应使用 PostgreSQL FTS 与 pgvector，记录 embedding 模型版本，并在模型、chunk 规则或索引变化时重新评估。
