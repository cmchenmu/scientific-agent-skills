# Lab Agent 完整使用手册（当前实现）

本手册以当前仓库代码为准，覆盖可实际调用的功能。当前本机服务已启动，直接在浏览器打开 `http://127.0.0.1:8000` 即可测试，不需要安装依赖、运行构建或准备数据库。

浏览器默认以 `Research Assistant Demo` 身份打开：在“知识问答”输入问题可查看授权证据和引用；在“模拟报销”创建任务后，使用审批按钮完成本地模拟审批与提交；“我的任务”会显示状态。所有演示状态保存在 `data/`，不连接真实财务或身份系统。

## 1. 功能状态

| 实践手册目标 | 当前状态 | 实际入口 |
| --- | --- | --- |
| 本地文档入库、去重、ACL 检索和可定位引用 | 可用 | `app.cli local ...`、`POST /v1/knowledge/query` |
| Europe PMC 开放获取 JATS 下载与 PostgreSQL 入库 | 已实现，需 PostgreSQL | `download-open-access`、`ingest` |
| 论文证据表和人工审核状态机 | 可用，仅本地归档 | `app.cli workflow ...` |
| 报销草稿、预览、审批、幂等提交 | 可用模拟器 | Python 调用 `LocalAdminAdapter` |
| 审计、脱敏、预算、ACL 缓存与发布门禁 | 可用本地实现 | 服务类、`release-check`、`launch-report` |
| OIDC/SSO、Redis/RQ、对象存储、模型调用、流式 Agent 编排 | 未接入 | 无 |
| 会话、任务、审批、产物 HTTP API | 未接入 | 无 |


本地演示不需要 PostgreSQL、Redis、对象存储、模型 API 或 `.env`。所有本地数据默认写入 `data/`，应保持在 Git 之外。日常使用仅需浏览器；第 10 节中的命令仅用于开发验收。

## 3. 本地知识库：入库、授权、检索和问答

本地模式使用 SQLite 和本地对象副本，支持 JATS XML、HTML、DOCX、PDF。单个文件最大 50 MiB；可执行文件头会被拒绝。该检查不是病毒扫描。

### 3.1 准备示例文档

创建一个不含敏感数据的 HTML 文件，例如 `data/demo/tissue-sop.html`：

```html
<title>Tissue SOP</title>
<h1>Storage</h1>
<p>Store tissue on ice before fixation.</p>
```

### 3.2 入库

```bash
uv run python -m app.cli local ingest \
  --archive data/local-archive \
  --project mouse-neuro-demo \
  --source data/demo/tissue-sop.html \
  --classification internal-research \
  --allowed-role student \
  --allowed-role research-assistant
```

输出包含文档 ID、`created` 或 `duplicate` 和 chunk 数。相同文件在同一项目中重复入库会得到 `duplicate`。查看记录和失败原因：

```bash
uv run python -m app.cli local list --archive data/local-archive --project mouse-neuro-demo
uv run python -m app.cli local errors --archive data/local-archive
```

### 3.3 授予本地教学用户角色

```bash
uv run python -m app.cli local grant-role \
  --archive data/local-archive \
  --user-id student-demo \
  --display-name 'Student Demo' \
  --project mouse-neuro-demo \
  --role student
```

本地归档的 ACL 同时检查项目、用户是否 active 和角色。不要在生产中把这个 CLI 当作权限管理接口。

### 3.4 检索和问答

直接按角色搜索：

```bash
uv run python -m app.cli local search \
  --archive data/local-archive \
  --project mouse-neuro-demo \
  --role student \
  --query 'tissue ice'
```

以用户身份问答：

```bash
uv run python -m app.cli local query \
  --archive data/local-archive \
  --user-id student-demo \
  --project mouse-neuro-demo \
  --question '组织固定前应如何保存？'
```

回答为 JSON。`status=answered` 时，`citations` 中包含 `document_id`、`chunk_id`、标题和章节/页码定位；`status=insufficient_evidence` 表示没有可授权的证据，不能将其当成否定结论。

## 4. HTTP 知识问答 API

当前 HTTP 应用只有两个路由：

| 方法和路径 | 用途 |
| --- | --- |
| `GET /health` | 健康检查 |
| `POST /v1/knowledge/query` | 对本地归档执行 ACL-first 问答 |
| `POST /v1/chat/stream` | SSE 返回 answer、citation、done 事件 |
| `GET /v1/session`、`GET /v1/tasks` | 本地开发会话与当前用户任务 |
| `POST /v1/actions/reimbursements...` | 报销预览、创建、审批、确认和取消 |
| `GET /v1/artifacts/{workflow_id}` | 当前工作流所有者读取论文草稿 |

启动服务前，指定归档目录：

```bash
export LOCAL_ARCHIVE_PATH="$PWD/data/local-archive"
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另一终端调用：

```bash
curl http://127.0.0.1:8000/health
curl -X POST http://127.0.0.1:8000/v1/knowledge/query \
  -H 'Content-Type: application/json' \
  -H 'X-User-Id: student-demo' \
  --data '{"project_id":"mouse-neuro-demo","question":"组织固定前应如何保存？"}'
```

缺少 `X-User-Id` 返回 401。该头只是教学接口的用户选择器，不是认证机制；暴露到网络前必须替换为 OIDC 验证和服务端加载的角色/项目策略。

## 5. PostgreSQL 文献管道（可选）

此路径用于从 Europe PMC 下载开放获取 PMC 全文并将 JATS XML 写入 PostgreSQL。它需要网络、有效的 `DATABASE_URL` 和已迁移的数据库。

```bash
export DATABASE_URL='postgresql+psycopg://labuser:labpass@127.0.0.1:5432/labagent'
uv run alembic upgrade head
uv run python -m app.cli seed-demo --project-name mouse-neuro-demo
```

保存上述命令输出的项目 UUID，然后下载并入库：

```bash
uv run python -m app.cli download-open-access \
  --query 'mouse hippocampus' --output data/inbox --limit 20

uv run python -m app.cli ingest \
  --project '<项目 UUID>' \
  --source data/inbox/PMCxxxx.xml \
  --classification internal-research \
  --allowed-role student

uv run python -m app.cli documents list --project '<项目 UUID>'
```

下载只接受开放获取、带 PMC 全文的研究文章，保留 `manifest.jsonl`、来源 URL、许可和 SHA-256。该 PostgreSQL 管道目前没有接入 HTTP 问答 API；在线 API 使用的是第 3 节的 `LocalArchive`。

## 6. 论文工作流

论文工作流只使用当前用户已授权的本地 chunks，状态依次为：

```text
draft -> search_plan_review -> retrieve -> ingest -> relevance_review
-> evidence_table -> manuscript_draft -> human_review -> completed | failed | cancelled
```

先完成第 3 节的入库和授权，然后创建工作流：

```bash
WORKFLOW_ID=$(uv run python -m app.cli workflow create \
  --root data/workflows \
  --archive data/local-archive \
  --user-id student-demo \
  --project mouse-neuro-demo \
  --question '组织固定前应如何保存？')
printf '%s\n' "$WORKFLOW_ID"
```

提交并人工审核检索计划：

```bash
uv run python -m app.cli workflow plan \
  --root data/workflows --archive data/local-archive \
  --workflow-id "$WORKFLOW_ID" \
  --query '组织 保存 固定' \
  --inclusion '已授权项目文档' \
  --exclusion '无 ACL 文档'

uv run python -m app.cli workflow advance \
  --root data/workflows --archive data/local-archive \
  --workflow-id "$WORKFLOW_ID" --action approve-plan --reviewer pi-demo
```

逐步执行，不要跳过中间状态：

```bash
for ACTION in retrieve ingest cards evidence draft; do
  uv run python -m app.cli workflow advance \
    --root data/workflows --archive data/local-archive \
    --workflow-id "$WORKFLOW_ID" --action "$ACTION"
done
```

`draft` 会输出草稿。它只列出现有证据；背景、方法、结果或讨论中证据不足的内容保持为 `TODO`。人工核对原始证据后完成或拒绝：

```bash
uv run python -m app.cli workflow advance \
  --root data/workflows --archive data/local-archive \
  --workflow-id "$WORKFLOW_ID" --action complete \
  --reviewer pi-demo --approved
```

省略 `--approved` 会将工作流置为 `failed`。每步均有 SQLite checkpoint；`--max-steps` 可限制创建时的可执行步数。CLI 目前没有查看/取消/恢复子命令，需要通过 `ManuscriptWorkflow.resume()` 或 `cancel()` 服务方法调用。

## 7. 行政报销模拟器

`LocalAdminAdapter` 是本地 SQLite 模拟器，不能提交真实报销。其固定政策为：类型 `reimbursement`、币种 CNY、金额不超过 500000 分（5000 元）、必须有项目/说明/至少一个凭证。完整顺序为：

```text
读取政策 -> 校验草稿 -> 预览 -> 创建审批任务 -> 非申请人审批
-> 服务端提交 -> 查询状态
```

以下代码可在项目目录以 `uv run python` 运行：

```python
from pathlib import Path
from app.services.admin_adapter import LocalAdminAdapter

adapter = LocalAdminAdapter(Path('data/admin-adapter'))
requester = {
    'id': 'student-1', 'active': True, 'roles': ['research-assistant'],
    'project_roles': {'proj-a': ['research-assistant']},
    'allowed_tools': {'proj-a': {
        'admin.get_policy', 'admin.validate_draft', 'admin.create_task',
        'admin.submit_reimbursement',
    }},
}
approver = {'id': 'finance-1', 'active': True, 'roles': ['finance-approver']}
payload = {
    'project_id': 'proj-a', 'amount_cents': 1200, 'currency': 'CNY',
    'description': 'taxi', 'receipts': ['receipt-1'],
}

print(adapter.get_policy(requester, 'reimbursement'))
print(adapter.validate_draft(requester, payload))
preview = adapter.preview_submission(requester, payload)
task_id = adapter.create_approval_task(requester, preview, 'reimburse-001')
adapter.record_approval(approver, task_id, preview.draft_hash, 'approved')
external_id = adapter.submit_approved_request(requester, task_id, 'reimburse-001')
print(adapter.get_request_status(requester, external_id))
```

申请人不能自审；审批绑定 `draft_hash`；重复使用同一个幂等键返回同一个模拟外部 ID。真实系统接入前必须替换为受机构批准的 API 客户端和 OAuth scope，并补齐超时、撤销、部分成功及人工转交处理。

## 8. 治理与上线检查

`GovernanceStore` 提供本地审计、敏感字段脱敏、预算和按用户/项目/角色隔离的缓存。`BudgetController` 和论文工作流的预算耗尽后都不应自动扩大预算或无限重试。

运行确定性门禁：

```bash
uv run python -m app.cli release-check
uv run python -m app.cli launch-report \
  --json-output /tmp/launch-readiness.json \
  --markdown-output /tmp/launch-readiness.md
```

`release-check` 检查路径穿越、预算停止、checkpoint 和评测集数量。`launch-report` 还会运行全量测试、Ruff、四类恶意输入、行政金额阈值和最小权限上线顺序。报告只有在所有检查通过时才为 `Ready: True`。

固定上线顺序是：

```text
knowledge_read_only -> analysis_drafts -> administrative_drafts -> approved_real_writes
```

通过本地报告不等于可以生产上线。生产前仍需完成 OIDC、数据库/对象存储、任务队列、真实系统 API、密钥管理、审计保留、数据保护、伦理和财务审批。

## 9. 常见限制和故障处理

- `uv: command not found`：先按 uv 官方安装说明安装，再执行 `uv sync`。
- API 返回 `insufficient_evidence`：检查项目名、用户是否已获角色、文档 ACL 是否包含该角色，以及检索词是否命中已入库 chunks。
- API 返回 401：提供 `X-User-Id`；仅限本地教学环境。
- 工作流提示状态不匹配：按第 6 节顺序推进，先由人工执行 `approve-plan`。
- PostgreSQL 迁移连接到 `driver://...`：在项目 `.env` 或环境中设置真实 `DATABASE_URL`，然后重试 `alembic upgrade head`。
- `web/` 无法启动可用页面：这是当前实现缺少 React `src/` 的结果，不是安装问题。
