# 论文实验提取实现文档

## 可行性与方案

需求适合采用 RAG 加 Agent 的分层实现，但不适合把 Agent 当成无约束的论文事实提取器。本项目当前交付的可测试闭环采用“ACL-first RAG + 确定性抽取和模板生成”：RAG 负责从授权论文中按语义与关键词检索，抽取器负责分类并保留证据，自动化器只选择预先审核的脚本模板。这样能防止模型从论文中臆测材料、样本量、结果或统计结论。

后续可在此边界内增加 Agent：它只能调用 `search_authorized_evidence`、`extract_experiment` 与受控模板选择工具；必须将每一个结构化字段绑定到返回的 `chunk_id`，对不存在的字段输出 `unknown`，不能执行下载脚本或访问未授权文档。高风险实验与统计解释仍需领域研究者复核。

## 架构

```text
关键词 -> Europe PMC 游标分页目录（总数不限，每页 <= 20 篇） -> 用户单选/多选/当前页下载
目录论文 -> JATS XML + PMC 文章页图像映射 -> 方法、表格、图注、真实 CDN 图片地址 -> 下载前预览
所选 PMC ID -> 全文下载、manifest、LocalArchive -> chunks + hash embeddings + ACL
关键词 -> 文档级聚合检索（固定 top 5） -> 论文选择
论文选择 + ACL 再校验 -> ExperimentExtractionService -> 原文证据字段
数据分析证据 -> 受控方法识别 -> 版本化 Python/CSV 模板 -> 用户下载与本地运行
```

`LocalArchive` 的现有入库层用 `pypdf` 提取 PDF 页文本、JATS 解析器提取 XML 章节、HTML/DOCX 解析器统一为 section/chunk。每个 chunk 保存文本、章节或页码、哈希向量和文档 ACL。`search_documents_for_user` 复用已有混合检索，并按一篇文献的最高得分 chunk 聚合，避免同一论文占满五个位置。

`ExperimentExtractionService` 在抽取前调用 `authorized_document`，随后从 `document_chunks_for_user` 获取该篇全文。两者都在 SQL 中连接 `users`、`user_roles`、`document_acl` 与项目，确保前端传入文献 ID 不会绕过授权。服务用中英文方法、材料、结果与结论关键词，结合章节标题筛选片段；返回 Pydantic `ExperimentExtraction`，证据包含 chunk、章节、页码和原文。结果最多八条，控制响应大小。

## 自动化策略

当前受控识别项为：

| 原文方法信号 | 产物 | 输入列 |
| --- | --- | --- |
| `t-test` / `t检验` | `two_group_t_test.py` | `group,value` |
| `ANOVA` / `方差分析` | `one_way_anova.py` | `group,value` |
| `regression` / `回归` | `linear_regression.py` | `x,y` |

模板仅使用 Python 标准库，避免生成时引入不受控依赖或把任意论文文本拼入可执行代码。输入格式、数值转换和最小行数检查被写入脚本。ANOVA 模板目前输出描述统计和分析前检查提醒，不伪装为完整推断实现；t 检验报告 Welch t 值；回归报告斜率与截距。生产升级应将审阅过的 `scipy/statsmodels` 版本、p 值、效应量、图形、协变量与多重比较策略封装进不同的固定模板，并对每个模板建立测试数据和统计金标准。

## HTTP 与前端

新增 `POST /v1/literature/catalog`、`GET /v1/literature/catalog/{pmcid}/inspection`、`POST /v1/literature/selected-import`、`POST /v1/literature/search` 与 `GET /v1/literature/{document_id}/experiment`。目录接口基于 Europe PMC `cursorMark` 分页，返回命中总数、每页最多 20 篇开放全文元数据及摘要，因此用户可以翻阅全部命中。`inspection` 先解析 Europe PMC JATS XML 的方法章节、`table-wrap` 和 `fig`，再从相同 PMCID 的 PMC HTML 页面匹配 `graphic` 文件名与 NCBI CDN 图片地址；不再猜测失效的 `/bin/` 路径。响应还包含基于已定位表格标题的确定性 `data_summary`。页面把表格原文放入折叠预览，显示图注和图片；没有可嵌入图片时提供原文链接。

这条下载前检查路径只处理开放全文，且是只读操作。它不会绕过付费墙或受限 PDF。扫描 PDF、补充材料、仅在图片中的数值，以及没有稳定图片资源的文章，必须在取得授权全文后由研究人员复核。表格标题、图注和正文均视为证据，不把它们当作对模型的指令。

受控 Agent 的正确接入方式是将 `inspection` 结果作为只读工具输出，限制模型只使用这些字段进行摘要，并要求每一项对应方法章节、表格编号或图号。模型必须对未提供的数值、图片内容和结论返回 `unknown`。当前网页先显示可审计的确定性提取结果，即使未配置模型凭据也可用；现有 Agent 服务已经遵循工具白名单和服务端 ACL 模式，生产中新增此只读工具时应沿用相同的参数校验、长度上限、审计和字段级来源绑定。

“我的论文库”使用 `GET /v1/library/documents` 列出经过 SQL ACL 过滤的文档元数据，`GET /v1/library/documents/{id}/original` 返回经再次 ACL 校验的原始对象流，`DELETE /v1/library/documents/{id}` 仅允许研究助理或 PI 删除。删除操作级联移除 chunks、标识符和 ACL，写入审计事件，并只在没有其他文档引用同一对象时删除本地对象文件。浏览器以 Blob 下载原文、分析脚本和 CSV，不向服务端写入用户数据。跨域、开发身份和已有 `X-User-Id` 约束保持不变。

影响因子通过 `LAB_AGENT_JCR_METRICS_PATH` 指向的本地 JCR 导出 JSON 提供。`journal_metrics.py` 仅匹配规范化期刊名和配置的 `jif/year`，因此分数来源可审计；没有授权数据或匹配项时返回空值而非以其他影响力指标替代。年份与影响因子均在当前已加载的结果集合中排序，未知 JIF 置后；这避免依赖 Europe PMC 的远程排序参数影响搜索可用性。

## 验证与限制

测试覆盖：文档级 top-5 限制、五类有证据抽取、t 检验模板及 CSV 列、越权/跨项目拒绝、HTTP 响应。运行：

```bash
cd /GIT/scientific-agent-skills/lab-agent
.venv/bin/python -m pytest tests/test_experiment_extraction.py -q
.venv/bin/python -m pytest -q
cd web && npm run build
```

哈希嵌入是本地开发基线，不能视为生产级语义检索；生产应替换为经过评测的嵌入模型和文档级重排序器。PDF 图像、表格、补充文件、复杂多因素统计和生物实验可重复性均不由当前版本保证。每个自动化分析输出都应在正式科研使用前经统计与领域专家审阅。
