# 启动数据库并执行迁移

本文说明如何启动本地 PostgreSQL（带 pgvector）、配置 `lab-agent`，并执行数据库迁移。命令分为两种场景：使用开发环境已经提供的 PostgreSQL，或在宿主机用 Docker 启动一套本地服务。

## 1. 先检查已有数据库

进入项目目录：

```bash
cd /GIT/scientific-agent-skills/lab-agent
```

检查连接配置是否已经注入：

```bash
env | grep '^DATABASE_URL=' || true
test -f .env && grep '^DATABASE_URL=' .env | sed 's#://[^@]*@#://<redacted>@#'
```

不要把 `.env` 内容提交到 Git。当前 Alembic 会自动读取 `lab-agent/.env` 中的 `DATABASE_URL`，不需要把密码写到 `alembic.ini`。

## 2. 启动本地 PostgreSQL（没有现成服务时）

以下命令在宿主机终端执行，不要在没有 Docker daemon 的开发容器内执行：

```bash
docker network inspect lab-agent-net >/dev/null 2>&1 \
  || docker network create lab-agent-net

docker run -d \
  --name lab-postgres \
  --network lab-agent-net \
  -e POSTGRES_USER=labuser \
  -e POSTGRES_PASSWORD=labpass \
  -e POSTGRES_DB=labagent \
  -p 5432:5432 \
  -v lab-pg-data:/var/lib/postgresql/data \
  pgvector/pgvector:pg17
```

等待容器就绪并启用向量扩展：

```bash
until docker exec lab-postgres pg_isready -U labuser -d labagent >/dev/null 2>&1; do
  sleep 1
done
docker exec lab-postgres psql -U labuser -d labagent \
  -c 'CREATE EXTENSION IF NOT EXISTS vector;'
```

如果容器已经存在，使用下面命令启动它，不要再次 `docker run`：

```bash
docker start lab-postgres
docker exec lab-postgres pg_isready -U labuser -d labagent
```

## 3. 配置项目连接

设置 `HOST_IP` 为开发容器可访问的宿主机地址（本机 Docker 场景通常是 `127.0.0.1` 或默认网关）：

```bash
HOST_IP=127.0.0.1
cat > .env <<'EOF'
DATABASE_URL=postgresql+psycopg://labuser:labpass@HOST_IP:5432/labagent
EOF
sed -i "s/HOST_IP/${HOST_IP}/" .env
```

确认只检查连通性，不输出密码：

```bash
uv run python - <<'PY'
import os
import psycopg
from dotenv import load_dotenv

load_dotenv(".env")
url = os.environ["DATABASE_URL"].replace("+psycopg", "")
with psycopg.connect(url) as connection:
    print("PostgreSQL:", connection.execute("SELECT 1").fetchone())
PY
```

预期输出：

```text
PostgreSQL: (1,)
```

## 4. 执行 Alembic 迁移

```bash
uv run alembic upgrade head
uv run alembic current
```

成功时，`current` 会显示：

```text
0001_initial_governance_schema (head)
```

这表示 Alembic 已连上 PostgreSQL，并创建了用户、角色、项目、文档、ACL、chunks、任务、审批、工具运行和审计事件表。

重复执行 `upgrade head` 是安全的：Alembic 会发现数据库已经在 head，不会重复创建表。

## 5. 常见问题

### `Can't load plugin: sqlalchemy.dialects:driver`

这说明 Alembic 使用了 `alembic.ini` 中的示例地址 `driver://user:pass@localhost/dbname`。检查 `.env` 是否存在且包含 `DATABASE_URL`：

```bash
grep '^DATABASE_URL=' .env
uv run alembic upgrade head
```

### `uv` 尝试下载无关的 Git 依赖并失败

如果根仓库的 `skills-ref` 因网络代理不可用导致 `uv run` 同步失败，可在已安装依赖的环境中执行：

```bash
uv run --no-sync alembic upgrade head
uv run --no-sync alembic current
```

这不会跳过数据库连接或迁移，只是禁止 `uv` 在本次命令前重新同步环境。

### 检查数据库容器

```bash
docker ps --filter name=lab-postgres
docker logs --tail 50 lab-postgres
docker exec lab-postgres pg_isready -U labuser -d labagent
```

## 6. 停止与清理

停止容器但保留数据：

```bash
docker stop lab-postgres
```

删除容器但保留 `lab-pg-data` 数据卷：

```bash
docker rm lab-postgres
```

只有确认不再需要本地数据库数据时，才删除数据卷：

```bash
docker volume rm lab-pg-data
```

生产环境不要使用本文中的示例密码；应使用受管 PostgreSQL、密钥管理系统和机构网络策略。
