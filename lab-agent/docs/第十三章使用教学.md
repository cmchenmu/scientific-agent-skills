# 第十三章使用教学：测试、红队与上线

第十三章把前面各章的安全边界集中成一个可重复的上线报告。报告不依赖真实外部服务，固定运行单元测试、Ruff、RAG 评测集、输入红队和最小权限上线顺序；任一门禁失败都返回非零状态，不应继续发布。

## 1. 已实现内容

| 文件 | 作用 |
| --- | --- |
| [launch_report.py](../app/launch_report.py) | 生成 JSON/Markdown 上线准备报告。 |
| [cli.py](../app/cli.py) | 新增 `launch-report` 命令。 |
| [test_launch_report.py](../tests/test_launch_report.py) | 评测集数量、上线顺序和报告状态测试。 |

报告固定检查：

1. `pytest -q` 全量测试；
2. `ruff check app tests`；
3. `tests/evals/knowledge_cases.jsonl` 至少 30 条；
4. 路径穿越、SQL、Shell、超大输入被拒绝；
5. 行政适配器金额阈值被拒绝；
6. 上线阶段遵循最小权限顺序并启用回滚开关。

## 2. 运行上线报告

在 `lab-agent/` 目录执行：

```bash
cd /GIT/scientific-agent-skills/lab-agent
uv run --no-sync python -m app.cli launch-report \
  --json-output /tmp/launch-readiness.json \
  --markdown-output /tmp/launch-readiness.md
```

预期报告：

```text
tests             pass
ruff              pass
eval_cases        pass
path_traversal    pass
sql_fragment      pass
shell_fragment    pass
oversized_input   pass
amount_threshold  pass
rollout_order     pass
Ready: True
```

使用 `--skip-commands` 只运行确定性的策略红队检查：

```bash
uv run --no-sync python -m app.cli launch-report --skip-commands
```

默认命令执行固定参数的 `pytest` 和 `ruff`，不接受模型或用户提供的 shell 字符串。报告 JSON 适合 CI，Markdown 适合人工审阅。

## 3. 红队场景

### 输入攻击

`validate_tool_arguments` 会拒绝：

- `../` 和 Windows 路径穿越；
- `DROP TABLE`、`DELETE FROM` 等 SQL 片段；
- `;`、管道、重定向、反引号和 `$()` 等 Shell 元字符；
- 序列化后超过 16 KiB 的输入。

报告只检查服务端拒绝结果，不能把“模型看到了恶意文本”误认为“系统执行了恶意文本”。文档中的提示注入仍应作为普通数据处理，不能改变权限或工具定义。

### 行政写入

报告重新验证第十一章的金额阈值：超过政策上限的报销草稿必须拒绝。完整审批、草稿 hash、幂等和外部状态测试仍由 `tests/test_admin_adapter.py` 覆盖。

### 权限和引用

第八章评测集包含跨项目、停用用户、伪造引用、无证据和提示注入文本场景；第十章测试工作流审核、checkpoint 和预算；第十二章测试脱敏、成本终止和 ACL 缓存。

## 4. 固定评测集

评测集位置：

```text
tests/evals/knowledge_cases.jsonl
```

每次修改 prompt、模型、chunk、embedding、ACL 查询或回答结构后，都必须重新运行完整报告。至少保留以下类别：

- 正确回答和带 citation 的回答；
- 无答案、证据冲突和版本冲突；
- 跨项目、无角色、停用用户；
- 恶意文档提示注入；
- 伪造或不在检索结果中的 citation；
- 空输入、超长输入和特殊字符。

评测结果不能替代领域专家核验；它只说明自动化边界在固定样例上没有退化。

## 5. 上线顺序

报告强制以下顺序：

```text
knowledge_read_only
-> analysis_drafts
-> administrative_drafts
-> approved_real_writes
```

每个阶段都必须有：少量试点用户、固定评测集、审计、回滚开关、错误转人工方案。不要一开始开放所有流程，也不要因为测试通过就跳过机构安全、伦理、财务和数据保护审批。

## 6. Agent 调用边界

Agent 不能自行决定“上线通过”。它只能读取报告状态并向用户说明失败门禁：

```text
run_launch_report() -> {checks[], ready}
```

当 `ready == false` 时，Agent 不得请求跳过失败检查、修改报告文件、扩大预算或直接启用真实写入。上线批准必须由具备权限的人完成，并在治理审计中留下操作者、版本、时间和回滚开关状态。

## 7. 常用验证命令

```bash

uv run --no-sync ruff check app tests

uv run --no-sync python -m app.cli launch-report \
  --json-output /tmp/launch-readiness.json \

```
