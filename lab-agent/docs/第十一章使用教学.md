# 第十一章使用教学：行政流程适配器

本章实现一个低风险的“报销材料校验 + preview + 审批后提交”模拟适配器。它不连接真实财务系统，所有状态保存在本地 SQLite；目标是先验证权限、业务规则、人工确认、幂等和审计，再替换为正式 OpenAPI/MCP 客户端。

## 1. 已实现的接口

实现文件：[admin_adapter.py](../app/services/admin_adapter.py)

```text
get_policy(user, request_type)
validate_draft(user, payload)
preview_submission(user, payload)
create_approval_task(user, preview, idempotency_key)
record_approval(approver, task_id, draft_hash, decision)
submit_approved_request(user, task_id, idempotency_key)
get_request_status(user, external_request_id)
```

模拟政策：

- 类型固定为 `reimbursement`；
- 货币固定为 `CNY`；
- 金额上限为 `500000` 分（5000 元）；
- 必须有项目、金额、说明和至少一个凭证引用；
- 正式提交必须由 `finance-approver` 或 `admin` 审批；
- 申请人不能审批自己的请求；
- 审批绑定 preview 生成的 `draft_hash`；
- `idempotency_key` 在 SQLite 中唯一，重复提交返回同一模拟外部 ID。

## 2. 为什么先用模拟服务

在没有系统所有者书面授权、正式 API 文档、OAuth scope、撤销规则和失败处理方案前，不应连接真实财务系统。当前适配器的 `external_requests` 表模拟外部服务，足以验证：

```text
policy -> validate -> preview -> human approval -> authorized commit -> status
```

真实系统接入时只替换最后一层 HTTP 客户端，保留同样的接口和测试；不要让 Agent 直接拼 URL、SQL、Shell 或任意 HTTP 请求。

## 3. 本地示例

```python
from pathlib import Path

from app.services.admin_adapter import LocalAdminAdapter

adapter = LocalAdminAdapter(Path("data/admin-adapter"))
requester = {
    "id": "student-1",
    "active": True,
    "roles": ["research-assistant"],
    "project_roles": {"proj-a": ["research-assistant"]},
    "allowed_tools": {
        "proj-a": {
            "admin.get_policy",
            "admin.validate_draft",
            "admin.create_task",
            "admin.submit_reimbursement",
        }
    },
}
approver = {"id": "finance-1", "active": True, "roles": ["finance-approver"]}
payload = {
    "project_id": "proj-a",
    "amount_cents": 1200,
    "currency": "CNY",
    "description": "taxi",
    "receipts": ["receipt-1"],
}

print(adapter.get_policy(requester, "reimbursement"))
print(adapter.validate_draft(requester, payload))
preview = adapter.preview_submission(requester, payload)
task_id = adapter.create_approval_task(requester, preview, "reimburse-001")
adapter.record_approval(approver, task_id, preview.draft_hash, "approved")
external_id = adapter.submit_approved_request(requester, task_id, "reimburse-001")
print(adapter.get_request_status(requester, external_id))
```

不要直接使用 `research-assistant` 角色文本作为可信授权来源；示例中的角色和 `allowed_tools` 应由服务端从认证主体和数据库策略构造。

## 4. 各步骤的边界

### `get_policy`

只返回服务端政策。Agent 可以用它解释缺少哪些字段，但不能修改金额阈值、审批角色或货币。

### `validate_draft`

检查字段集合、金额范围、货币、说明和凭证引用；额外字段会拒绝。参数还会经过第九章的路径、SQL、Shell 和大小安全检查。

### `preview_submission`

返回规范化 payload、影响摘要和 `draft_hash`。preview 不产生外部写入，用户必须看到金额、项目、凭证和“将产生外部写入”的影响提示。

### `create_approval_task`

保存草稿和幂等键，状态为 `pending_approval`。同一幂等键不能创建第二个任务。

### `record_approval`

只有 `finance-approver` 或 `admin` 能审批；审批记录绑定精确的 `draft_hash`。申请人自审会被拒绝。

### `submit_approved_request`

服务端再次执行当前用户授权、草稿 hash、审批和幂等检查。没有有效审批时不会创建外部请求。网络重试时先查询幂等键；已提交则直接返回原外部 ID。

### `get_request_status`

申请人或管理员可以查询状态，其他用户不能通过外部 ID 读取请求信息。

## 5. Agent 调用流程

Agent 只能使用以下结构化工具：

```text
get_policy(authenticated_user, request_type)
validate_draft(authenticated_user, payload)
preview_submission(authenticated_user, payload)
create_approval_task(authenticated_user, preview_id, idempotency_key)
get_request_status(authenticated_user, external_request_id)
```

提交是高影响操作，应由服务端在审批完成后调用：

```text
submit_approved_request(authenticated_user, task_id, idempotency_key)
```

Agent 不得：

- 自己批准请求或模拟审批人身份；
- 修改 preview 后复用旧审批；
- 把请求金额拆分绕过阈值；
- 读取其他用户的请求状态；
- 在超时后盲目重试外部提交；
- 将真实 token、原始票据或完整财务 payload 写入日志。

推荐顺序：

```text
认证 -> 读取政策 -> 校验草稿 -> 展示 preview -> 用户确认
-> 创建审批任务 -> 财务审批 -> 服务端二次授权
-> 幂等提交 -> 保存外部 ID -> 查询状态 -> 脱敏审计
```

## 6. 替换为真实系统

在 `LocalAdminAdapter` 通过测试后，再实现一个独立的 `FinanceApiAdapter`：

1. 使用机构批准的 OpenAPI/MCP schema 固定输入和输出字段。
2. 使用受限 OAuth scope；token 只从服务端凭据存储读取。
3. `preview_submission` 只做本地验证和远端 dry-run，不执行正式写入。
4. `submit_approved_request` 带服务端生成的幂等键和审批 ID。
5. 超时先调用状态查询接口，不能无条件重试 POST。
6. 保存外部请求 ID、状态、响应摘要和 trace ID，禁止记录 token 和完整票据。
7. 设计撤销、人工转交和 API 不可用时的回滚方案。
