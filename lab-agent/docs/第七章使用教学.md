# 第七章使用教学：确定性文献入库

本章实现了一个不依赖聊天模型的文献入库流程：从 Europe PMC 检索开放获取 PMC 全文、下载 JATS XML、保存来源清单、计算 SHA-256、按章节分块、写入 ACL 与全文检索索引，并生成可复现的本地基线向量。

## 离线完整模式

除了 PostgreSQL 演示管道，当前项目还提供完全本地的 `local` 模式。它不读取 `.env`、不连接 PostgreSQL、Redis、S3 或模型 API；原始文件、SQLite 元数据、对象副本、ACL、审计事件和错误记录都保存在一个本地目录中。

支持 JATS XML、HTML、DOCX 和 PDF。PDF 以页码作为回溯定位；HTML 以标题和段落分段；DOCX 从 OOXML 提取段落；JATS XML 保留原有章节和段落定位。输入有 50 MiB 上限，并拒绝可执行文件头，但这不是替代正式病毒扫描的安全保证。

### 本地模式命令

```bash
uv run --no-sync python -m app.cli local ingest \
  --archive data/local-archive \
  --project offline-demo \
  --source path/to/approved-document.html \
  --classification internal-research \
  --allowed-role student \
  --allowed-role research-assistant

uv run --no-sync python -m app.cli local list \
  --archive data/local-archive --project offline-demo

uv run --no-sync python -m app.cli local search \
  --archive data/local-archive --project offline-demo \
  --role student --query hippocampus

uv run --no-sync python -m app.cli local errors \
  --archive data/local-archive
```

`local ingest` 输出 `created` 或 `duplicate`、文档 ID 和 chunk 数。重复判定使用同一项目的 SHA-256，以及 DOI/PMID/PMCID（可从 JATS XML 提取）。`local search` 在 SQLite 查询中先做角色 ACL 过滤，未授权角色得到空结果。

### Agent 调用流程

Agent 只能把用户已授权的、明确指定的本地文件交给入库工具；不能自行浏览目录、下载付费或受限文献、扩大角色范围，或在搜索结果之外引用内容。

1. 服务端验证调用者可向目标项目投递，并把允许角色、分类、固定文件路径作为结构化参数传给 `local ingest`。
2. Agent 调用 `local ingest`，只读取其 `created`、`duplicate` 或错误结果；失败时调用 `local errors` 获取受限错误摘要。
3. Agent 调用 `local list` 确认文档已建立，不能把“下载成功”误报为“已入库”。
4. 需要回答问题时，服务端根据认证用户的角色调用 `local search`。Agent 只能根据返回 chunks 回答，并附带文档标题和 chunk ID；空结果必须明确说明没有已授权证据。

可将上述命令包装为四个受控工具：`ingest_local_document`、`list_local_documents`、`search_local_documents`、`list_ingestion_errors`。不要提供任意 shell、任意 SQL 或由模型构造的文件路径工具。

## 本次已完成的示例

- 检索边界：Europe PMC 中 `OPEN_ACCESS:Y`、`SRC:PMC`，且匹配 `(mouse OR mice OR rodent) AND (brain OR neuroscience OR neuron OR hippocampus OR cortex)`。
- 下载结果：20 篇开放获取 PMC JATS XML。
- 本地文件：`data/inbox/mouse-neuroscience-20/`，其中 `manifest.jsonl` 为每篇文章记录 PMCID、标题、期刊、许可文本、来源 URL 与响应 SHA-256。
- 数据库项目：`mouse-neuro-demo`，项目 ID 保存在该目录的 `project_id.txt`。
- 入库结果：20 个 `documents`、953 个 `chunks`、40 条角色 ACL 授权。每个 chunk 均保存章节、段落定位和 `hash-v1` 向量版本。

下载文件属于本地实验数据，已被 `.gitignore` 排除，不应提交到仓库。

## 1. 命令与职责

| 命令 | 职责 |
| --- | --- |
| `seed-demo` | 初始化固定角色和一个示例项目，输出项目 UUID。 |
| `download-open-access` | 只下载 Europe PMC 标记为开放获取的 PMC JATS XML，并写 JSONL 来源清单。 |
| `ingest` | 验证项目和角色 ACL，按 SHA-256 去重，写入文档、ACL、全文索引和 chunks。 |
| `documents list` | 列出项目已入库文档。 |

代码入口是 [app/cli.py](../app/cli.py)，解析和入库逻辑在 [app/services/ingestion.py](../app/services/ingestion.py)。

## 2. 前置条件

进入项目目录并确认第六章的迁移已完成：

```bash
cd /GIT/scientific-agent-skills/lab-agent
uv run --no-sync alembic current
```

输出应包含：

## 3. 下载 20 篇开放获取全文

下面的查询只从 PMC 选择开放获取文献；下载器还会拒绝标记为摘要、勘误、编辑评论或读者来信的结果。

```bash
uv run --no-sync python -m app.cli download-open-access \
  --query '(mouse OR mice OR rodent) AND (brain OR neuroscience OR neuron OR hippocampus OR cortex)' \
  --output data/inbox/mouse-neuroscience-20 \
  --limit 20
```

检查下载完整性：

```bash
find data/inbox/mouse-neuroscience-20 -name 'PMC*.xml' -type f -size +0c | wc -l
wc -l data/inbox/mouse-neuroscience-20/manifest.jsonl
```

两项都应为 `20`。不要将检索片段当作全文证据；后续问答和人工审查应依据 XML 的正文、章节与来源清单。

## 4. 创建项目并写入 ACL

首次运行时创建项目和第六章定义的角色：

```bash
PROJECT_ID=$(uv run --no-sync python -m app.cli seed-demo --project-name mouse-neuro-demo)
printf '%s\n' "$PROJECT_ID"
```

为文献设置最小权限。这里仅授予 `student` 与 `research-assistant` 的读取权限：

```bash
for source in data/inbox/mouse-neuroscience-20/PMC*.xml; do
  uv run --no-sync python -m app.cli ingest \
    --project "$PROJECT_ID" \
    --source "$source" \
    --classification internal-research \
    --allowed-role student \
    --allowed-role research-assistant
done
```

`classification` 是业务分类的显式输入，并被继承写入每个 chunk 的元数据。没有 `--allowed-role` 时命令失败，不会创建没有 ACL 的可检索文档。

## 5. 验证入库、去重与追溯

列出文档：

```bash
uv run --no-sync python -m app.cli documents list --project "$PROJECT_ID"
```

对同一文件再次执行 `ingest`，输出应以 `duplicate` 结束，不会新增文档或 chunks。去重依据是同一项目下的 SHA-256；生产环境还应把 DOI、PMID、PMCID 设为跨来源的规范化去重键。

检查数据库状态：

```bash
uv run --no-sync python - <<'PY'
import os
from pathlib import Path
import psycopg
from dotenv import load_dotenv

load_dotenv(Path('.env'))
project_id = Path('data/inbox/mouse-neuroscience-20/project_id.txt').read_text().strip()
url = os.environ['DATABASE_URL'].replace('+psycopg', '')
with psycopg.connect(url) as connection:
    with connection.cursor() as cursor:
        cursor.execute('SELECT count(*) FROM documents WHERE project_id = %s', (project_id,))
        print('documents:', cursor.fetchone()[0])
        cursor.execute('SELECT count(*) FROM chunks c JOIN documents d ON d.id = c.document_id WHERE d.project_id = %s', (project_id,))
        print('chunks:', cursor.fetchone()[0])
        cursor.execute('SELECT count(*) FROM document_acl a JOIN documents d ON d.id = a.document_id WHERE d.project_id = %s', (project_id,))
        print('acl grants:', cursor.fetchone()[0])
        cursor.execute('SELECT count(*) FROM chunks c JOIN documents d ON d.id = c.document_id WHERE d.project_id = %s AND c.embedding IS NOT NULL', (project_id,))
        print('embedded chunks:', cursor.fetchone()[0])
PY
```

本次示例的预期是 `20`、`953`、`40`、`953`。chunk 的 `metadata` 记录 `section`、`paragraph` 和 `page: null`：JATS XML 没有可靠的 PDF 页码，因此章节与段落是本批文献的精确回溯定位。

## 6. 向量与生产注意事项

初版使用 `hash-v1`：256 维、归一化、基于稳定 SHA-256 的词哈希向量。它保证了离线可复现、无需密钥，也实际写入了 `chunks.embedding`，但不适合作为高质量的语义检索模型。

进入第八章前，应选择一个版本固定的科学文本嵌入模型，记录模型名、版本、维度、输入 hash 和生成时间，并对所有现有 chunks 重新索引。检索时必须先按 document ACL 和项目过滤，再执行全文或向量召回。

## 7. 已知边界

- 当前确定性解析器实际支持 JATS XML；命令会拒绝 PDF、DOCX、HTML，直到为每种格式增加有测试的提取器。
- 下载器只接受开放获取 PMC 全文，不使用浏览器 cookie、机构订阅或付费墙内容。
- 本示例未加入 5 份脱敏 SOP；真实项目应通过独立的受控投递流程加入，并保留版本和生效日期。
- 文件校验通过不等于科研内容正确。应由领域专家审查纳入标准、许可、版本、研究质量和结论。
